クイックソート：ピボットを選んで、残りを分ける

再生を押すと、動画をYouTubeから読み込みます。

タワーを1つ選び、それより低いものを左に、高いものを右に置くと、そのタワーはちょうど収まるべき位置に入ります。両側にも同じことをすれば、列全体が並び終わります。
両端から中ほどへ進む2つの目印を使って12個のタワーを分割し、クイックソートがなぜその場で（インプレースで）動き、実際にはたいてい最速の並べ替えになるのかを確かめます。さらに、唯一の弱点（すでに並んでいる列と、悪いピボット）を見つけて、ピボットをランダムに選ぶことで直します。

ナレーション全文

タワーを1つ、どれでもいいので選びます。それより低いものは全部その左に、高いものは全部その右に置きます。そのタワーは、もうちょうど収まるべき位置にあります。両側にも同じことをすれば、列全体が並び終わります。今日はクイックソート。実際のソフトウェアの多くに入っている並べ替えと、その唯一の弱点です。

選んだタワーを「ピボット」と呼びます。ここでは、いちばん最後の7を選びます。2つの目印が、両端から出発します。left の目印は右へ進み、ピボットより高いものが見つかるまで進みます。right の目印は左へ進み、ピボットより低いものが見つかるまで進みます。この2つは、どちらも間違った側にいるので、入れ替えます。そのまま続けて、2つの目印がすれ違うまで進めます。最後に、ピボットが2つの部分のあいだのすき間に入れ替わります。余分な列はいりません。すべて、その場で（インプレースで）行われます。

次に、両側それぞれに、同じ方法でクイックソートをします。ピボットは、それぞれ別に選びます。部分はどんどん小さくなって、最後はどれも1つのタワーだけになります。平均すると、およそ n log n ステップ。マージソートと同じです。実際には、すべての中でいちばん速いことがよくあります。その場で並べ替えを進め、メモリーを順番にたどっていくので、キャッシュが大好きな動きです。

ただし、弱点があります。すでに並び終えている列を渡し、ピボットにはいつも最後のタワーを選ぶとしましょう。どのピボットも、残りの中でいちばん高いタワーです。片側にはすべてが入り、もう片側には何も入らず、1段ごとにタワーが1つしか減りません。つまり、log n 段ではなく、およそ n 段になります。n² に逆戻りで、手作業で並べ替えるのと同じです。

直し方は簡単です。ピボットをランダムに選ぶのです。こうすると、どの段でも悪い分け方になる可能性はごくわずかで、実際には、まず起こりません。

クイックソート。ピボットを選び、それを境に分け、両側でも同じことを繰り返します。次回は、n log n より速い並べ替えはあるのでしょうか。あります。ただし、2つの要素を一度も比べない並べ替えだけです。また会いましょう。
