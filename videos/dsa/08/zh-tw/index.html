文字稿

隨便挑一座積木塔。比它矮的全放在它左邊，比它高的全放在它右邊。這座塔現在就在它該在的位置上了。兩邊各自再這麼做，整排就排好了。今天要講：快速排序，很多真實軟體裡用的就是它，還有它唯一的弱點。

挑出來的這座塔，叫做基準（pivot）。這裡我們拿最後一座：7。兩個標記從兩端出發。名叫 left 的標記往右走，直到碰到比基準高的；名叫 right 的標記往左走，直到碰到比基準矮的。這兩座都站在錯的那一半，所以把它們交換。然後繼續走，直到兩個標記交錯。最後，基準換到兩半中間的空位。不需要另外一排，一切都在原地完成。

接著對兩邊各自做快速排序，各挑各的基準。每一段越來越小，直到每段只剩一座塔。平均下來，大約是 n log n 步，和合併排序一樣。實際使用時，它常常是最快的。它在原地完成，而且按順序走過記憶體，這正是快取最喜歡的。

不過它有個弱點：給它一排已經排好的，而且總是拿最後一座塔當基準。每一個基準都是剩下的塔裡最高的。一邊拿到全部，另一邊什麼都沒有，每一層只剝掉一座塔。這樣就是大約 n 層，而不是 log n 層。又退回 n²，就跟用手排序一樣。

解決辦法很簡單：隨機挑選基準。這樣一來，每一層都分得很偏的情況幾乎不可能出現，實際上就是不會發生。
