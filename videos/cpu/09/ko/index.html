수가 명령이 되는 방법: 기계어 명령어

이 16비트 수는 명령어예요. 프로세서에게 레지스터 두 개를 더하라고 알려 줘요.
아주 작은 명령어 집합을 만들고, 명령어를 필드(연산 코드, 레지스터, 수)로 나누고, 네 가지 주소 지정 방식을 써 봐요. 5와 3을 더해 답을 저장하는 네 줄짜리 프로그램을 쓰고, 마지막으로 두 가지 큰 설계 방식인 RISC와 CISC를 비교해요.

이 영상의 애니메이션은 모두 코드로 그렸고, 내레이션은 AI 음성이에요.

전체 대본

여기 16비트짜리 수가 있어요. 메모리 안에서는 색깔이나 글자가 될 수도 있어요. 하지만 프로세서가 이것을 명령어로 읽으면 이런 뜻이 돼요. 레지스터 2를 레지스터 1에 더하라. 오늘은 수가 어떻게 명령이 되는지 알아봐요.

모든 프로세서에는 할 수 있는 일을 적은 정해진 목록이 있어요. 이걸 명령어 집합이라고 해요. 명령어마다 자기만의 코드 번호가 있어요. 아주 작은 명령어 집합을 직접 만들어 봐요. 우리 명령어는 길이가 16비트이고, 여러 필드로 나뉘어 있어요. 처음 4비트는 연산 코드(옵코드)로, 어떤 연산을 할지 정해요. 0010은 더하기라는 뜻이에요. 그다음 2비트는 레지스터 하나를 고르고, 그다음 2비트는 두 번째 레지스터를 골라요. 우리 프로세서에는 레지스터가 네 개 있고, 0번부터 3번까지 번호가 붙어 있어요. 마지막 8비트에는 명령어에 필요할 때 수나 메모리 주소가 들어가요. 0과 1을 쭉 적는 건 너무 힘들어서, 사람들은 대신 짧은 이름을 써요. ADD R1, R2처럼요. 이걸 어셈블리어라고 해요. 어셈블러라는 프로그램이 이걸 다시 수로 바꿔 줘요.

명령어가 데이터를 어디에서 가져올지 알려 주는 방법은 몇 가지가 있어요. 이걸 주소 지정 방식이라고 해요. 즉시 주소 지정: 수가 명령어 안에 들어 있어요. LOAD R1, #5는 5를 곧바로 레지스터 1에 넣어요. 레지스터 주소 지정: 데이터가 이미 레지스터에 있어요. ADD R1, R2는 두 레지스터를 더해요. 직접 주소 지정: 명령어에 메모리 주소가 들어 있어요. LOAD R1, [12]는 메모리 12번 칸에 저장된 것을 무엇이든 가져와요. 간접 주소 지정: 주소를 레지스터가 가지고 있어요. LOAD R1, [R2]는 R2에 들어 있는 주소에서 읽어요. R2를 바꾸면 같은 명령어가 다른 칸을 읽어요. 이렇게 프로그램은 목록을 차례로 훑어 가요.

프로그램은 이런 수들이 메모리에 차례로 놓여 있는 것일 뿐이에요. 5와 3을 더해서 답을 15번 칸에 저장하는 프로그램이에요. 5를 불러오고, 3을 불러오고, 더하고, 저장해요. 명령어 네 개, 64비트예요.

실제 명령어 집합은 크게 두 가지 방식이 있어요. RISC, 즉 축소 명령어 집합은 모든 명령어를 단순하게 유지해요. 길이가 모두 같고, 명령어마다 작은 일 하나만 해요. CISC, 즉 복합 명령어 집합은 명령어가 훨씬 많아요. 긴 것도 있고, 명령어 하나가 메모리에서 불러와서 더하는 것처럼 여러 단계를 한 번에 해내기도 해요. 휴대폰과 최근 노트북 상당수는 RISC 설계를 써요. 데스크톱 PC는 대부분 CISC 설계를 쓰지만, 칩 안에서는 어차피 큰 명령어를 작고 단순한 단계로 쪼개요.

정리하면, 명령어는 필드로 나뉜 수예요. 연산 코드와, 데이터를 어디서 찾을지가 들어 있어요. 프로그램은 그런 명령어들의 목록이에요. 그런데 이 수들을 하나씩 읽고 실제로 실행하는 건 누구일까요? 다음 편에서는 CPU가 프로그램을 실행하는 방법을 알아봐요. 거기서 만나요.
