文字稿

四筐衣服，每筐都要洗、烘、叠，每一步一小时。一筐做完再做下一筐，从头到尾要十二个小时。可第一筐一进烘干机，洗衣机就空出来了，马上洗下一筐。这样四筐六个小时就全做完。同样的机器，一半的时间。今天就讲 CPU 里的同一招。

上一集我们的 CPU 一次只做一条指令：取指、译码、执行，再下一条。执行的时候，取指那部分就干等着。那就叠起来做：第一条在执行，第二条就在译码，第三条已经在取指。每一拍，每一段把手上的活交给下一段，中间隔着小寄存器。这就是流水线。一条指令从头到尾还是要三拍，可流水线装满以后，每一拍都有一条指令做完。真正的处理器分得更细：教材里的经典设计是五段，现在很多芯片有十几段以上。

可是叠着做也会出问题。看这两条：先 ADD R1, R2，再 SUB R3, R1。减法要用新的 R1，可它在译码那段读寄存器的时候，加法还没做完，它拿到的是旧值。这叫数据冲突。

一个办法是停一下：让第二条晚一拍，中间放一个空格子——气泡——顺着流水线流下去。答案对了，可是慢了。

更好的办法是转发：答案其实已经在 ALU 的输出端了，直接接回 ALU 的输入，下一条指令马上就能用。不用等。大多数处理器时时刻刻都在这么做。

跳转带来另一个大麻烦：等跳转定下来的时候，流水线早把它后面的指令取进来了。要是真跳了，这两条就是错的，只好扔掉，从新的地址重新装流水线。流水线越深，每猜错一次浪费的拍子就越多，所以现在的 CPU 会提前猜每次跳转往哪儿去。这是下一集的内容。

总结一下：流水线把指令叠起来做，每一拍做完一条；冲突会捣乱，停顿和转发保证答案对。下一集：让现在的 CPU 飞快的几招——猜跳转、不按顺序执行，还有好几个核一起干。下集见。
