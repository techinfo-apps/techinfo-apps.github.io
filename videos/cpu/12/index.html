CPU Pipelining: How Processors Overlap Instructions

Transcript

Four loads of laundry. Each one needs washing, drying, and folding: an hour each. One load at a time, start to finish, takes twelve hours. But the moment the first load moves to the dryer, the washer is free. Start the next one. Now all four are done in six hours. Same machines, half the time. Today: the same trick, inside a CPU.

Last time, our CPU did one instruction at a time: fetch, decode, execute, then the next. While it executes, the fetch part just waits. So let's overlap them. While the first instruction executes, the second is being decoded, and the third is being fetched. Each stage hands its work to the next on every clock tick, through small registers in between. That's a pipeline. One instruction still takes three ticks from start to finish. But once the pipeline is full, one instruction finishes on every single tick. Real processors cut the work into more stages: five in the classic textbook design, and more than a dozen in many modern chips.

But overlapping causes trouble. Look at these two instructions: ADD R1, R2, then SUB R3, R1. The subtraction needs the new R1. But when it reads its registers in the decode stage, the addition hasn't finished yet. It would get the old value. This is called a data hazard.

One fix: stall. Hold the second instruction back for a tick, and let a bubble, an empty slot, flow down the pipeline instead. Correct, but slower.

A better fix: forwarding. The answer already exists at the output of the ALU. Wire it straight back to the ALU's input, so the next instruction can use it right away. No waiting. Most processors do this all the time.

Jumps cause the other big hazard. By the time a jump is decided, the pipeline has already fetched the instructions after it. If the jump is taken, those instructions are wrong. They're thrown away, and the pipeline refills from the new address. With deep pipelines, every wrong guess wastes many ticks. So modern CPUs try to guess where each jump will go. That's next time.

So: a pipeline overlaps instructions, so one finishes on every tick. Hazards get in the way, and stalls and forwarding keep the answers right. Next time: the tricks that make modern CPUs fast: guessing jumps, running instructions out of order, and using many cores at once. See you there.
